# Polls and quizzes

Copy `PollHandler.kt` into a Spring Boot application using the Telegram starter. Send `/poll` or `/quiz`, then vote. The handler receives the answer and sends a message back to the chat where the poll was created. `request.telegramPollOrigin()` provides the poll ID, original chat ID and message ID when available. Chengine automatically uses the original chat for a response with no explicit chat ID.

The mapping is recorded after Chengine successfully sends a poll (including polls inside a response list). The default in-memory store is isolated by bot identity, holds at most 100,000 entries, and expires entries 30 days after creation; mappings are lost on restart. Configure `ChengineTelegramLongPoolingBot.pollOriginStore` before processing to use a shared durable `TelegramPollOriginStore`. Use the same stable bot username across restarts. A storage failure after Telegram accepts a poll cannot undo the send. Updates racing with the initial storage, polls sent outside Chengine, missing or expired mappings, and polls created before enabling the store may have no known origin. Check `telegramPollOrigin()` before replying; a reply without an explicit chat ID and without a known origin fails clearly.

Individual `poll_answer` updates are sent only for non-anonymous polls created by the bot. Votes can be retracted, in which case `optionIds` may be empty; a voter may be represented by `voterChat` rather than `user`. Anonymous polls provide aggregate `poll` updates, not individual answers. Poll updates do not create a conversation session. The original chat identifies where the poll was sent, not necessarily the voter's chat.
